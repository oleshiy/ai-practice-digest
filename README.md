# Практики ИИ

Русские редакционные дайджесты: опыт компаний, исследования, стоимость, проверка качества и ограничения.

Сайт: https://oleshiy.github.io/ai-practice-digest/

В репозитории находятся готовые компактные выпуски, отдельный архив находок и статический сайт. Пересказы сохраняют ссылки на источники; утверждения компаний не выдаются за независимые измерения.

## Сборка

Для сборки нужен Python 3.11 или новее, для проверки поиска — Node.js. Внешних библиотек нет:

```sh
python3 build.py
python3 check.py
node test_archive.js
node test_releases.js
python3 test_publisher.py
python3 test_navigation.py
python3 test_thematic.py
python3 test_provided_source.py
python3 test_working.py
```

Результат находится в `_site/`. GitHub Actions автоматически собирает и публикует его в GitHub Pages после изменений в `main`.

## Новый выпуск

Добавьте один готовый Markdown в `content/`. Перед текстом обязательны только `date`, `type` (`daily`, `weekly`, `last10`, `last30`, `top30` или `working`) и `title`; имя имеет вид `YYYY-MM-DD-латинский-slug.md` или `prefix-YYYY-MM-DD-латинский-slug.md` (префикс: латинская буква, затем латинские буквы/цифры). Заголовок `#` в тексте должен совпадать с `title`. По желанию можно добавить `label`, `subtitle`, `window`, `count` и параметры существующего формата; без них сборщик подставит безопасные значения. Сохраните даты окна, оговорки, исходные ссылки и полный список только вошедших в выпуск находок там, где он обязателен. Дайджест не заменяет архив: последний доступен на `findings.html`, с поиском, фильтрами по источнику и периоду и постраничным просмотром. Сборщик сам создаёт страницу выпуска, полный каталог и главную; `index.html`, `archive.html` и отдельный manifest вручную не редактируются.

`working` — отдельная рабочая подборка для чтения и выбора материала. Она видна на главной и в каталоге с собственным названием типа, после календарных выпусков той же даты; полный weekly сохраняет своё место. Этот тип не обозначает ещё один стандартный недельный выпуск и не задаёт время чтения.

Внутри длинной темы допустимы подзаголовки четвёртого уровня (`####`): они делят рассказ на части, но не создают новые темы в оглавлении и архиве находок.

```md
---
date: 2026-09-11
type: daily
title: AI за 11 сентября
---

# AI за 11 сентября
```

Поддерживаемая разметка выпусков: заголовки, абзацы, нумерованные и маркированные списки, ссылки, выделение и встроенный код. Не добавляйте HTML или исполняемый код в тексты выпусков. Проверка отклоняет неверную дату, тип, metadata или имя файла; одноимённый slug невозможен, потому что он берётся из уникального имени файла. При переименовании добавьте `redirect_from: прежний-slug` в metadata нового файла: старый адрес станет переходом с сохранением query и якоря, canonical указывает на новый адрес. Алиас не создаёт второй выпуск и не входит в индексы; совпадения с именами выпусков или другими алиасами запрещены.

Архив находок (`findings.html`) собирается при сборке из самих выпусков: каждый заголовок третьего уровня и каждая строка раздела «Остальное» становятся находкой со ссылкой на источник и на выпуск. Отдельного файла с находками нет; новый выпуск попадает в архив при следующей публикации.

Для тематического weekly можно задать `sections` — точное число разделов второго уровня, — а сценарии оформить заголовками третьего уровня. Тогда обязательны «Что из этого применить в платформе» и «Все находки выпуска»: одна строка списка на сценарий со всеми его ссылками, в порядке текста. `count` задаёт число сценариев; при наличии `details` и `shorts` их сумма должна совпадать с `count`. Проверка старых выпусков сохраняет прежний формат.

### Два точных представления одного предоставленного письма

В `2026-11-01-weekly` разрешена ровно одна тема без публичной ссылки: письмо OpenAI получателю Pro, предоставленное пользователем. Для неё нужны metadata `provided_source: openai-pro-email-2026-11-01`, обычный H3 `OpenAI удвоила лимиты Work и Codex в Pro и готовит общий бюджет использования` и отдельная строка:

```text
Источник — письмо OpenAI получателю Pro, предоставлено пользователем 1 ноября; дата отправки и публичная ссылка неизвестны.
```

В конечном индексе эта тема записывается без ссылки: `N. <тот же заголовок>. <та же строка источника>`. Для полного выпуска маркер действует только при этом slug, типе `weekly` с `sections`, точном заголовке и описании источника; дополнительных HTTP-ссылок в теме и строке индекса нет. Неверный или неиспользованный маркер, второй материал без ссылки и расхождение индекса отклоняются. Без маркера требования к публичным ссылкам прежние. Архив сохраняет находку с меткой «Письмо OpenAI» и ссылкой на точный раздел выпуска; это локальный разбор, а не публичный оригинал письма. Дата выпуска в архиве не обозначает дату отправки письма.

То же письмо разрешено в отдельной рабочей подборке `2026-11-01-weekly-short` типа `working` с `sections`, прежним маркером и ровно одним обычным H3 `OpenAI удвоила лимиты Work и Codex в Pro`. Строка источника остаётся дословно прежней. Дополнительные публичные материалы в этой теме обязательны ровно в таком порядке:

1. https://help.openai.com/en/articles/20001626-api-credits-benefit-for-eligible-chatgpt-subscriptions
2. https://latent.space/p/ainews-google-admits-ai-mode-hurts-search-revenue-15-500b-drop-worst-since-2004-ipo-ai-bear-market-c/
3. https://x.com/claudeai/status/2116220869479428500

В индексе сохраняется обычный текст `N. <точный заголовок>. <точная строка источника>`, затем ` · [API-кредиты](URL1) · [Обзор Latent Space](URL2) · [Claude Ultra](URL3)`. Подписи дополнительных ссылок могут отличаться; их число, URL и порядок — точные. Ни заголовок, ни его начало в индексе не становятся ссылкой на API-кредиты. Архив выбирает локальный раздел письма до поиска публичных ссылок в его тексте. Это два точных разрешённых представления одного письма, по одной теме в каждом выпуске, без расширения на другие slug, типы, заголовки или источники.

### Иллюстрации

Для согласованных изображений используйте отдельную строку `![Русский alt](assets/name.png)`, сразу за ней — `Подпись: Описание и [источник](https://example.com)`. Генератор создаёт figure с подписью и ссылкой на полный размер. Допустимы существующие PNG непосредственно в assets с именем из строчных латинских букв, цифр, дефисов и подчёркиваний. Изображения копируются в сайт без преобразования; внешние URL, обходы путей и остальные форматы не поддерживаются. Проверка: `python3 test_figures.py`.

При удалении заголовков внутри уже опубликованного выпуска можно явно зарезервировать их прежние номера: `reserved_heading_ids: 4,5`. Сборщик пропускает эти номера у следующих заголовков, сохраняя старые ссылки на оставшиеся темы; удалённые якоря ведут в начало текста. Значения должны быть положительными, уникальными и отсортированными.
