# Главное за неделю: семь тем для команды AI-платформы




### OpenAI удвоила лимиты Work и Codex в Pro

OpenAI планирует объединить Chat и Work: в одном разговоре можно будет обсудить идею и поручить ChatGPT сделать сайт, презентацию или выполнить работу в интернете. Файлы и плагины подключаются там же; пользователь следит за работой и направляет её. Сначала интерфейс протестируют на небольшой группе. Codex останется отдельным режимом настольного приложения.

С 29 октября лимиты Work и Codex в Pro удвоены. В ближайшие недели ChatGPT и Codex получат общий лимит: расход зависит от модели и задачи, остаток и время восстановления будут видны в настройках. Instant останется безлимитным и не будет расходовать общий запас.

Для подходящих подписок Pro и Business появились отдельные API-кредиты на собственные приложения. Нужно связать подписку с API-организацией.

У проверенных аккаунтов Claude Ultra, по обзору Latent Space, сняли пятичасовой лимит. Недельный сохранился.

Источник — письмо OpenAI получателю Pro, предоставлено пользователем 1 ноября; дата отправки и публичная ссылка неизвестны.

### [Anthropic перенесла Messages API с Python на Rust с помощью Claude](https://latent.space/p/opus55/)

Anthropic с помощью Claude перенесла Messages API с Python на Rust, чтобы снизить потребление процессорных ресурсов. Через этот API приложения обращаются к Claude.

Инженеры выбрали язык, спроектировали систему, составили план и проверяли результат. Claude писала реализацию и помогала обсуждать технические решения. На старте Rust-разработчиков в команде не было; по ходу наняли двух опытных специалистов.

Переносили существующее поведение без добавления новых функций. Python-версия продолжала развиваться: статический анализ кода помогал находить изменения, которые требовалось перенести в Rust.

Новую версию проверяли на копиях рабочих запросов, сравнивая ответы с Python-версией, затем постепенно переводили на неё пользователей.

По приблизительной оценке участницы проекта Кейтлин Лессе, потребление CPU снизилось на 40–50%, а время до первого токена — на 10–20%.

### [Artificial Analysis v5: новые тесты увеличили разрыв между Kimi и Opus](https://artificialanalysis.ai/articles/artificial-analysis-intelligence-index-v5)

Artificial Analysis обновила набор тестов, из которых складывается общий рейтинг моделей. В прежней версии Kimi K3.1 Pro и Claude Opus 5.5 набирали 55 и 58 баллов, в новой — 46 и 58. После смены заданий разрыв вырос с трёх до двенадцати баллов.

В рейтинг включили FrontierCode 2.0 — тест на исправление реальных ошибок в проектах. Например, агент должен починить отправку накопленных данных после восстановления интернета и сохранить совместимость библиотеки с существующими приложениями. Проверяют устранение ошибки и выполнение требований проекта. Нарушение обязательного требования обнуляет результат задачи.

Также добавили Terminal-Bench-Science — 70 научных задач по биологии, физике, математике и другим дисциплинам. Агент решает их на компьютере, результат проверяют автоматические тесты. Здесь Kimi выполнила 34% заданий, а лидер GPT-6 Astra — 63%. При этом в Terminal-Bench 4.0, который проверяет программирование, настройку систем и обработку данных, Kimi лидировала с 67%. Новая версия рейтинга учитывает оба набора задач.

Это сравнение на момент запуска v5 27 октября. На следующий день первое место заняла Gemini 4 Carbon с 59 баллами.

### [Replit Cloud Agents: от идеи сотрудника до проверенного изменения продукта](https://replit.com/blog/anyone-can-bring-ideas-to-company-codebase)

Replit Cloud Agents позволяют сотрудникам без навыков программирования предлагать изменения в рабочем продукте компании. Сотрудник описывает задачу, агент работает с настоящим репозиторием в среде, которая обновляется из основной ветки.

Агент меняет код, запускает приложение, проверяет его в браузере и создаёт запрос на включение изменений с видео результата. Инженер проверяет код и поведение приложения, принимает изменение или оставляет замечания. Агент дорабатывает решение по этой обратной связи.

Для нашей идеи Internal Lovable здесь интересна связь с существующими продуктами: сотрудник может довести предложение до работающей реализации, а инженер контролирует, что попадёт в продукт.

Cloud Agents доступны в Pro и Enterprise. В раннем доступе Replit также пробует сохранять замечания инженеров как постоянные навыки агента — после одобрения инженером.

Источники: [Replit Cloud Agents](https://replit.com/blog/anyone-can-bring-ideas-to-company-codebase)

### [Anthropic использует самооценку Claude для выявления злоупотреблений](https://safeguards.anthropic.com/2026/self-assessment/)

Anthropic специально обучила Claude выявлять злоупотребления в собственных разговорах. Сначала модель училась на диалогах с оценками более сильной модели, которой дали внутренние правила безопасности. Затем обучение с подкреплением поощряло правильные оценки.

Проверка запускается сразу после ответа пользователю: скрытый служебный запрос просит Claude оценить состоявшийся разговор. Система повторно использует KV-кэш — сохранённые промежуточные вычисления по диалогу. По оценке Anthropic, это добавляет менее 2% вычислений на охваченном API-трафике.

Каждую ночь сигналы собирают по клиентским организациям. Организации с несколькими серьёзными сигналами передают команде расследований; люди проверяют нарушения и принимают меры. Проверка происходит после ответа, поэтому остановить его выдачу она уже не может.

В сентябре эти сигналы помогли обнаружить использование Claude Code для автоматизированного мошенничества через романтические знакомства. После расследования Anthropic заблокировала связанные аккаунты.

Источники: [Anthropic, Self-assessment от 16 октября](https://safeguards.anthropic.com/2026/self-assessment/)

### [SWE-Shift: успех GPT-6 Astra падает с 67% до 25% при изменении условий](https://arxiv.org/abs/2610.32196)

SWE-Shift проверяет, как AI-агенты учитывают чужие правки и новые требования, появившиеся во время выполнения задачи.

Исследователи сохраняют промежуточное состояние и запускают два продолжения: с изменением условий и без него. Проверяют, решил ли агент задачу с учётом обновлений.

На 120 сценариях GPT-6 Astra в Codex справилась с 67% задач при неизменных условиях и с 25% — после вмешательства. В этом эксперименте способность закончить задачу сильно зависела от того, оставалась ли рабочая среда прежней.

Источники: [SWE-Shift, публикация от 23 октября](https://arxiv.org/abs/2610.32196)

### [Claude Smart reports: как команда использует ИИ и что можно улучшить](https://support.claude.com/en/articles/16893491-get-started-with-smart-reports)

Smart reports в Claude Enterprise анализируют выборку рабочих диалогов за период до 28 дней: какие задачи решали, сколько они стоили и что мешало получить результат.

Компания может задать свои вопросы к анализу. Отчёт покажет ответы, долю соответствующих сессий и расходов, позволит открыть конкретные примеры.

Он также предлагает, какие повторяющиеся приёмы оформить в общие skills и какие правила добавить в репозиторий, чтобы команда могла использовать накопленный опыт.

Стоимость считается по каталожным ценам. Имена по умолчанию скрыты; использовать отчёт для оценки личной производительности сотрудников запрещено.

Источники: [Smart reports](https://support.claude.com/en/articles/16893491-get-started-with-smart-reports)

## Что из этого применить в платформе

1. **Проверить замену реализации одного сервиса.** Зафиксировать поддерживаемые запросы и ошибки, сравнить старую и новую версии на сохранённых случаях и разрешённых копиях запросов. Отдельно контролировать внешние побочные действия и потребление CPU на запрос; для LLM-сервиса — также время до первого токена. После допуска включать новую версию постепенно с возможностью возврата.

2. **Добавить изменение условий в проверку coding-агента.** На копии рабочего проекта сохранить промежуточное состояние и запустить два продолжения: без изменения условий и с правкой коллеги или новым требованием. Сравнить, решил ли агент задачу с учётом обновлений.

3. **Проверить Smart reports на задачах команды.** Задать вопросы к выборке рабочих диалогов за период до 28 дней, посмотреть доли сессий и расходов и открыть конкретные примеры. Рассмотреть предложенные общие skills и правила для репозитория. Учитывать каталожные цены и запрет оценки личной производительности сотрудников.
