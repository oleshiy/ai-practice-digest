# Главное за неделю: семь тем для команды AI-платформы

### OpenAI удвоила лимиты Work и Codex в Pro

В письме получателю Pro OpenAI сообщила об удвоении включённого объёма Work и Codex с 29 октября. В ближайшие недели компания планирует общий лимит использования ChatGPT и Codex: расход будет зависеть от модели и сложности задачи, Unlimited Instant этот лимит не тратит. Отдельно на небольшой группе начнут тестировать Work прямо в обычном чате: пользователь сможет подключить файлы и плагины, поручить ChatGPT сделать сайт, собрать презентацию или выполнить работу в интернете. Пользователь сможет смотреть, что получается, направлять работу и проверять результат. Codex останется отдельным режимом в настольном ChatGPT.

Для приложений и API-пилотов подходящим подпискам Pro и Business доступны отдельные [API-кредиты](https://help.openai.com/en/articles/20001626-api-credits-benefit-for-eligible-chatgpt-subscriptions): подписку связывают с API-организацией после семи дней, остаток сгорает в конце расчётного периода; действуют региональные условия. По [обзору Latent Space](https://latent.space/p/ainews-google-admits-ai-mode-hurts-search-revenue-15-500b-drop-worst-since-2004-ipo-ai-bear-market-c/), у проверенных аккаунтов [Claude Ultra](https://x.com/claudeai/status/2116220869479428500) снят пятичасовой лимит, а недельный сохранён; новые аккаунты ждут проверки.

Источник — письмо OpenAI получателю Pro, предоставлено пользователем 1 ноября; дата отправки и публичная ссылка неизвестны.

### [Anthropic перенесла Messages API на Rust с помощью Claude](https://latent.space/p/opus55/)

Anthropic переписала Python-реализацию Messages API на Rust с помощью Claude. Люди выбрали язык, спроектировали систему и подготовили план; Claude писала реализацию. На старте Rust-разработчиков в команде не было, по ходу наняли двух опытных специалистов. Выделенная команда переносила прежнее поведение без собственных новых функций, а статический анализ отслеживал функции, которые другие команды продолжали добавлять в Python.

На копиях рабочих запросов сравнивали результаты Python и Rust, затем новую реализацию включали постепенно. В [первичном интервью Latent Space](https://latent.space/p/opus55/) Кейтлин Лессе приблизительно оценивает снижение потребления CPU после переноса в 40–50%, сокращение времени до первого токена — в 10–20% ([запись с 56:05](https://www.youtube.com/watch?v=vLRAYJqC4VA&t=3365s)).

### [Artificial Analysis v5: новые тесты изменили оценку Kimi](https://artificialanalysis.ai/articles/artificial-analysis-intelligence-index-v5)

27 октября Artificial Analysis пересобрала Intelligence Index. В новой версии Kimi K3.1 Pro получила 46 баллов против 58 у Claude Opus 5.5; в прежней было 55 и 58. Opus проверяли с максимальной глубиной рассуждения, в старом результате также использовался fallback. Баллы относятся к разным наборам заданий и весам.

В оценку программирования добавлен [FrontierCode 2.0](https://cognition.com/blog/frontier-code-2.0): сопровождающие проектов задают требования к принимаемому изменению, а провал обязательного условия обнуляет попытку. Terminal-Bench-Science проверяет исследовательскую работу в терминале. Код, наука, профессиональные задачи и общие знания теперь имеют равный вес. Kimi сильнее отстала в HLE-Diamond — проверке знаний и рассуждения — и научных задачах, сохранив лидерство на Terminal-Bench 4.0 в стартовом сравнении.

### [Replit превращает идеи сотрудников в проверяемые изменения кода](https://replit.com/blog/anyone-can-bring-ideas-to-company-codebase)

Сотрудник без навыков разработки описывает изменение рабочего продукта. Replit Cloud Agent меняет код в среде с актуальной основной веткой, запускает приложение, проверяет его в браузере и прикладывает видео к запросу на включение изменений. Инженер видит и код, и поведение приложения и принимает работу либо возвращает замечания. Cloud Agents доступны в Pro и Enterprise; превращение замечаний в постоянные навыки требует одобрения инженера и пока находится в раннем доступе.

### [Claude оценивает злоупотребления после собственного ответа](https://safeguards.anthropic.com/2026/self-assessment/)

Anthropic специально обучила Claude замечать возможные злоупотребления в собственных разговорах. Сначала модели показывали синтетические диалоги с оценками более сильной модели, которой дали внутренние правила безопасности компании; затем обучение с подкреплением поощряло корректные оценки. После ответа пользователю Claude получает короткую скрытую инструкцию и оценивает весь разговор: возможный вредный запрос, его категорию, отказ и приоритет проверки человеком.

Система повторно использует KV-кэш — сохранённые промежуточные вычисления разговора — и выдаёт примерно десять токенов оценки. Anthropic оценивает добавку менее чем в 2% вычислений на выдачу ответов в своём API-трафике. Ночью сигналы объединяют по клиентским организациям: организации с несколькими высокоприоритетными сигналами передают команде расследований для проверки людьми. Рабочая самооценка выполняется после ответа и его не блокирует.

### [SWE-Shift проверяет агента, когда задача меняется на ходу](https://arxiv.org/abs/2610.32196)

В исследовании от 23 октября из одного состояния coding-агента запускают два продолжения: обычное и с новым требованием, правкой коллеги или устаревшим результатом проверки. Нужно завершить задачу, сохранить действительные чужие изменения и заново подтвердить результат. В одном случае GPT-5.6 Sol удалила добавленный коллегой API Django, хотя все 39 прежних тестов прошли.

На 120 сценариях с девятью возможными моментами вмешательства GPT-6 Astra в Codex в режиме xhigh выполняла около 67% продолжений без изменения и 25% — после него. Веткам давали одинаковый бюджет в миллион суммарных входных и выходных токенов. На каждый запуск приходилось одно вмешательство; часть сценариев использовала общие исходные задачи.

### [Claude: отчёты о работе, бюджеты команд и учёт через API](https://support.claude.com/en/articles/16893491-get-started-with-smart-reports)

Smart reports анализируют выборку диалогов Claude за период до 28 дней: группируют работу и результаты, показывают каталожную стоимость, повторные переделки и ошибки инструментов. Из отчёта можно перейти к отдельным сессиям и найти, какую интеграцию исправить или какое действие оформить общим навыком. Имена по умолчанию скрыты, их раскрытие фиксируется в журнале; отчёты запрещено использовать для кадровой оценки.

[Общий месячный пул команды](https://support.claude.com/en/articles/17005973-manage-pooled-group-budgets-on-enterprise-plans) действует вместе с личным потолком сотрудника; в тарифах с оплатой мест он ограничивает дополнительное использование. Для программного учёта [Usage and Cost Analytics API](https://platform.claude.com/docs/en/manage-claude/usage-cost-analytics-api) даёт разрезы по моделям, рабочим пространствам, пользователям и сервисным аккаунтам, а в Console — ещё по API-ключам. `amount` учитывает скидки до кредитов, `list_amount` — каталожную цену. Бета-API обновляет данные обычно за четыре часа, иногда до суток.

## Что из этого применить в платформе

1. **Проверить замену реализации одного сервиса.** Зафиксировать поддерживаемые запросы и ошибки, сравнить старую и новую версии на сохранённых случаях и разрешённых копиях запросов. Отдельно контролировать внешние побочные действия и потребление CPU на запрос; для LLM-сервиса — также время до первого токена. После допуска включать новую версию постепенно с возможностью возврата.

2. **Добавить изменение условий в проверку coding-агента.** На копии рабочего проекта после сохранённого состояния внести правку коллеги или новое требование. Проверять сохранение нужного API и актуальность результатов проверок; обязательные требования определить до запуска и сравнивать модели в одной среде.

3. **Собрать один финансовый отчёт по рабочему сценарию.** Сопоставить тип выполненной работы с модельными расходами, отдельно сохранить каталожную стоимость, скидки и кредиты. Проверить, как работают личный потолок и общий пул команды при исчерпании каждого из них; данные с задержкой использовать для анализа, а лимит исполнять отдельным контролем.
