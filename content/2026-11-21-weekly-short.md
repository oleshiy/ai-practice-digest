# Короткий практический weekly · 16–21 ноября 2026

## Экономия

### OpenAI — снижение стоимости фоновых запросов GPT‑6.2 в Responses API

На GPT‑6.2 Astra и Sol обычный фоновый запрос с `background=true` идёт без скидки. В публичной бете окно ожидания `2h` снижает цену токенов на 30% от тарифа Standard, а `8h` — на 40%. Для ночного разбора документов задайте `service_tier="default"` и `background_options.completion_window="8h"`, оставив потоковую выдачу выключенной. Восемь часов — целевой срок первого ответа. Если модель запросит инструмент, окну следующего запроса нужно задать значение заново. [Руководство OpenAI](https://developers.openai.com/api/docs/guides/background)

### Microsoft — расходы на токены по сотрудникам и бюджеты командных процессов

Microsoft Digital показывает каждому сотруднику, сколько стоят его обращения к ИИ. Разовые поручения компания советует выполнять в чате, включённом в лицензию. Если несколько сотрудников регулярно решают одну задачу, выделите её в командный процесс, назначьте владельца и бюджет. Тогда команда сможет сопоставить расход токенов с объёмом выполненной работы. [Практика Microsoft Digital](https://www.microsoft.com/insidetrack/blog/maximizing-return-on-token-spend-how-were-approaching-finops-for-ai/)

### LangSmith — полная стоимость работы агента над каждым pull request

LangSmith складывает расходы всех сессий агента, связанных с одной правкой. В бета-версии видно, сколько стоило изменение, которое команда приняла, закрыла или ещё обсуждает. Откройте самый дорогой принятый pull request и посмотрите по его сессиям, какие модели вызывал агент и на какие сессии ушло больше всего денег. Ревью и расследования без собственной правки учитывайте отдельно. [Разбор LangSmith](https://www.langchain.com/blog/langsmith-coding-agents-roi)

### Microsoft Research TokenEconomizer — экономия токенов у кодовых агентов

Плагин запоминает команды и пути к файлам из прошлых задач, убирает лишние описания инструментов и подсказывает другой ход, когда агент зациклился. Microsoft Research проверила пять сочетаний агента и модели на одних и тех же 277 задачах SWE-Bench из шести репозиториев. В зависимости от сочетания плагин снизил среднюю стоимость задачи на 18–31% при близкой доле решений. Испытайте плагин на серии задач одного проекта и учитывайте стоимость его собственных вызовов. Первые задачи могут подорожать, пока плагин набирает опыт. [Исследование Microsoft](https://www.microsoft.com/en-us/research/blog/tokeneconomizer-learning-from-experience-to-make-ai-coding-agents-more-efficient/)

### Langfuse AI Gateway — LLM-прокси с учётом расходов и сохранением кэша запросов

Langfuse показывает расходы по ключу, сотруднику и команде. Шлюз передаёт запрос в формате провайдера и сохраняет метки кэширования, поэтому модель может повторно использовать уже обработанное начало запроса. Для пробы измените адрес API у одного агента, выдайте ему ключ шлюза и повторите запрос с тем же началом. Проверьте, сколько входных токенов провайдер прочитал из кэша и какую стоимость показал Langfuse. [Устройство шлюза](https://langfuse.com/blog/2026-11-11-building-the-langfuse-ai-gateway)

## Инженерные практики

### Claude Code — библиотека проверок по прошлым инцидентам для ревью изменений агента

После правки формата сессий агент Claude Code пробует открыть старый диалог, в котором ещё нет нового поля. Так команда проверяет совместимость. Возьмите один прошлый сбой и сохраните рядом с кодом условие запуска проверки, действие и ссылку на инцидент. При ревью агент выбирает проверки по изменениям в коде и читает правила из базовой ветки, чтобы сама правка не могла их ослабить. [Практика команды Claude Code](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/)

### Netflix — проверка плана агента перед запуском и переход на запасной план

В AI Discover модель собирает план подбора фильмов из разрешённых операций поиска и ранжирования. До запуска Netflix проверяет, есть ли у каждого шага входные данные, нет ли циклов и ведут ли шаги к одной странице рекомендаций. Для своего агента подготовьте заранее проверенный маршрут и запускайте его, если предложенный план ошибочен или модель не уложилась в отведённое время. [Опыт Netflix](https://netflixtechblog.com/engineering-ai-discover-e244944cdc38?source=rss----2615bd06b42e---4)

### Arize Phoenix и NVIDIA NeMo Guardrails — поиск нарушений, которые пропустил фильтр

В учебном примере NeMo остановил прямую просьбу вернуть деньги, но после переформулировки помощник пообещал возврат. Оба вызова в журнале завершились штатно. Поручите другой модели проверить конечный ответ по правилу поддержки и сопоставьте её оценку с решением фильтра по идентификатору запроса в Phoenix. Подтверждённый пропуск сохраните как тест для следующей версии фильтра. [Пример Arize](https://arize.com/resources/how-to-trace-and-evaluate-nvidia-nemo-guardrails-with-phoenix/)

### Arize Phoenix и OpenAI Agents SDK — обнаружение записи запросов после отключения трассировки

В примере Arize отключение трассировки в Agents SDK убрало записи о шагах агента. В том же окружении работал второй сборщик, который продолжал отправлять в Phoenix полные запросы к модели и ответы. Отключите трассировку, отправьте тестовую фразу и поищите её в Phoenix. Если фраза сохранилась, замените автонастройку явным подключением только нужного сборщика или разделите окружения агента и сервера Phoenix. [Разбор Arize](https://arize.com/resources/how-to-trace-the-openai-agents-sdk-with-phoenix/)

### LangChain Knowledge Factory — обновление инструкций агента по правкам сотрудников

LangChain показывает на примере отчёта, как сохранить две поправки. Рабочий агент замечает переименованный столбец в базе, а сотрудник исправляет заголовок отчёта. Отдельный агент-куратор просматривает замечания и сверяет изменения с рабочими документами. Начните с одного регулярного отчёта и передайте куратору замечание агента о новом столбце и переписку, в которой сотрудник исправил заголовок, чтобы в следующий раз агент сразу взял нужный столбец и оформил результат по согласованному образцу. [Пример LangChain](https://www.langchain.com/blog/knowledge-factory)

### LangSmith Tool Gateway — MCP-прокси с управлением доступом к инструментам

В публичной бете Tool Gateway можно задать, какие инструменты доступны каждому агенту и от чьего имени он их вызывает. В примере LangChain помощник магазина работает с правами вошедшего сотрудника, а ночная сверка остатков использует служебную учётную запись. Разделите эти два набора прав и добавьте подтверждение человеком для операций, которые изменяют данные. [Описание Tool Gateway](https://www.langchain.com/blog/langsmith-tool-gateway)

### Stripe — оценка кодовых агентов по доле задач, где выполнены все требования интеграции

На 69 платёжных сценариях Stripe проверила 14 сочетаний модели и среды разработки. Средняя оценка по критериям составила 78%, а все обязательные условия агенты выполнили лишь в 29% случаев. Stripe оценивала код и переписку без запуска интеграций. Для своей проверки выпишите обязательные условия каждого сценария, включая редкие случаи вроде возврата денег до отгрузки. Считайте долю задач, в которых агент учёл каждое условие. [Методика Stripe](https://stripe.dev/blog/stripe-integration-evals-methodology)
