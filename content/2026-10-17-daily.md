# 17 октября: Imprint ускоряет ревью, DeepSeek открывает поиск, агенты получают память

## Главное

### [Ускорение ревью кода с помощью small-change](https://lethain.com/small-changes/)

В Imprint средний инженер сливает в основную ветку в четыре раза больше запросов на изменение кода, чем два года назад. Проверка стала узким местом: медианное время ревью за тот же период выросло с 33 до 77 минут. Команда ввела small-change — ускоренный путь для ограниченного класса изменений.

Допуск определяет CI — автоматическая сборка и проверка кода. Она выставляет GitHub check — автоматическую отметку допуска, которую автор не может изменить вручную. Для допуска изменение должно содержать меньше тысячи строк, не иметь серьёзных замечаний, обозначенных у команды как p1 и p2, от AI-ревьюера и затрагивать ограниченное число сервисов. Автору нужны как минимум десять ранее принятых изменений в каталогах каждого затронутого сервиса. Общие библиотеки исключены, а файл .small_change позволяет закрыть ускоренный путь для отдельных участков, например движения денег.

После этого агентная процедура review-small-change рассматривает открытые изменения: повторно проверяет все проверки, включая сам допуск, и не даёт ускоренного одобрения изменениям, связанным с платежами или безопасностью. Другая процедура, review-pr-cluster, просматривает группы изменений и ищет повторяющиеся темы для обсуждения и новых автоматических проверок. Если small-change приводит к ошибке, команда должна исправить механизм проверки, инструкции агенту или CI.

Человеческая проверка сохраняется там, где её требуют действующие правила компании: для части репозиториев изменения обязан независимо просмотреть человек. Ускоренный путь не означает, что это требование уже отменено.

На внедрение ушло около двух дней с непостоянным вниманием участников. Пока требованиям соответствует примерно десятая часть изменений. Автор прямо пишет, что полезный замер результата ещё рано давать: сокращение времени ревью после запуска не показано. Расширять допуск будут вместе с усилением проверок. Это особенно трудно в продукте, где разные клиенты используют разные настройки: постепенное включение изменения небольшой группе пользователей покрывает меньше вариантов поведения.

**Что это меняет для нас.** Ускоренное одобрение можно разрешать программно по опыту автора, области изменений и результатам проверок. Самого ярлыка «маленькая правка» для такого разрешения недостаточно.

### [Tencent Hunyuan открыла Hy Memory 2.0 с рабочей памятью и памятью кода для агентов](https://pandaily.com/tencent-hunyuan-hy-memory-2-0-open-source-working-code-memory-memhub-apache-2)

Tencent открыла три части Hy Memory 2.0: модель для обработки памяти, сам фреймворк и локальное приложение MemHub. Их можно использовать вместе или отдельно. Код фреймворка выпущен под Apache 2.0.

Новая рабочая память и память кода сохраняют цель задачи, принятые решения, промежуточные результаты и уроки вместе с условиями их применимости. Перед продолжением длинной работы система сначала определяет текущую задачу, затем извлекает относящиеся к ней решения, ещё пригодный опыт и историю действий. Память разговоров собирает разрозненные факты в события с людьми, местом и временем, объединяет дубли и разрешает противоречия до передачи контекста модели.

Отдельная модель Hy-Memory-30B-A3B обучена извлекать сведения для памяти и разрешать противоречия. Подключение фреймворка к агенту идёт через SDK — библиотеку для разработчика. MemHub после разрешения пользователя переносит историю из подключённых инструментов в локальное хранилище и синхронизирует новые сессии. Заявлены десять интеграций, в том числе Cursor, Codex и DeepSeek Harness. У приложения есть командная строка и клиент для Mac. Tencent сообщает об использовании стека внутренними командами, но сохранённая публикация не раскрывает результат этих внедрений.

### [Claude пишет около 90% кода Claude Code](https://www.latent.space/p/ainews-high-taste-testers-ep-1)

Команда Claude Code сообщает, что Claude пишет около 90% кода продукта. С июня по сентябрь число принятых запросов на изменение кода удвоилось, а доля впоследствии отменённых изменений уменьшилась более чем на 40%.

В [цитате, сохранённой Simon Willison](https://simonwillison.net/2026/Oct/16/code-review/), авторы разбора команды Claude Code описывают ревью как постоянную обратную связь во время разработки. По их словам, большинство изменений Claude хотя бы раз проверяет и исправляет ещё до передачи человеку. Вместо одного вопроса «прочитал ли человек код?» команда спрашивает, что может пойти не так и какая проверка — автоматическая или человеческая — обнаружит проблему. Это описание практики авторов, без численного замера результата в самой цитате.

Это наблюдение команды о собственном процессе. Доля отменённых изменений — не число всех дефектов и не прямое измерение производительности инженера. Сохранённая рассылка не показывает контрольную команду или весь объём человеческого ревью, поэтому нельзя приписать изменение показателей одной лишь доле кода, написанного моделью. Сигнал относится к сочетанию объёма принятых изменений и их последующей устойчивости.

### [Modal ImageFS: файловая система для песочниц виртуальных машин](https://www.latent.space/p/ainews-high-taste-testers-ep-1)

Modal перевела песочницы виртуальных машин на ImageFS. Файловая система подгружает данные по мере обращения и распределяет их между уровнями хранения, а для ext4 — файловой системы внутри Linux — выглядит обычным диском. Приложению поэтому не требуется специальный способ читать файлы из нового хранилища.

Это конкретное устройство среды для запуска кода агентов: образ не обязательно целиком загружать заранее. В сохранённом обзоре нет измерения времени запуска или расходов, поэтому экономию от такого подхода он пока не подтверждает.

### [Zephon на TorchTitan: одинаковые данные после смены числа GPU](https://www.latent.space/p/ainews-high-taste-testers-ep-1)

PyTorch сообщает о проверке Zephon на TorchTitan: обучение, остановленное на 16 графических ускорителях (GPU), продолжили на 8, 32 и 64 GPU. Глобальные пакеты обучающих данных после возобновления совпали побитово — это проверили по контрольным суммам SHA-256.

Проверка касается того, какие данные получает очередной шаг обучения при изменении числа ускорителей. Она полезна для возобновления работы на другой конфигурации, но не доказывает побитового совпадения весов модели или всех вычислений: таких результатов рассылка не приводит.

### [UBTECH представила Thinker-WM: общую модель видео, глубины и действий робота](https://pandaily.com/ubtech-thinker-wm-unified-world-model-rgb-depth-action-worldolympiad-ewmbench-worldarena)

UBTECH описала Thinker-WM — модель мира, которая учится совместно предсказывать изображение, расстояние до объектов и действия робота. Обычно за видео, геометрию и выбор действий отвечают разные модули. Здесь каждый вид данных сначала получает своё кодированное представление, затем общий Transformer — вычислительный блок, связывающий видео, геометрию и действия, — обрабатывает их в одном внутреннем пространстве. На выходе модель снова строит видео, карту глубины и команды движения.

Глубина здесь — полноценный результат модели. В опытах с отдельными задачами RoboTwin её добавление повысило долю успешных манипуляций на 15 процентных пунктов по сравнению с вариантом без глубины. Это наиболее понятная проверка того, зачем объединять представления. Она не означает такой же прирост во всех задачах или на реальных производствах.

Одна и та же модель работает в шести режимах: разработчик меняет, какие данные известны и какие нужно получить. Например, по видео можно предсказывать действия. При обучении движения разных роботов представлены положением рабочего органа — захвата или другого инструмента на конце руки — с отметкой типа робота. Подготовка данных включает проверку качества и согласование видео с глубиной. Чтобы проверить, связаны ли зрительные признаки с движением, команда оставила основную модель неизменной, а небольшой новый модуль учила восстанавливать смещение рабочего органа по её внутреннему представлению изображения. Это исследование UBTECH, а не отчёт о внедрении на заводе.

### [Возвращение Meta: организация лаборатории и устойчивость конкуренции](https://www.interconnects.ai/p/meta-shakes-up-the-frontiers-open)

Nathan Lambert из Interconnects связывает возвращение Meta к передовым открытым и закрытым моделям с организацией исследований. В беседе руководителей Meta он выделяет большую самостоятельность исследователей и большой объём вычислений на каждого. По его пересказу, у Alexandr Wang больше двухсот прямых подчинённых: между руководителем и исследователями мало промежуточных управленческих уровней. Предполагаемый механизм — меньше решений, зависящих от бюрократии и внутренней политики. Причинная связь с качеством моделей здесь не измерена.

Lambert сравнивает лаборатории по тому, насколько регулярно они выпускают сильные модели: Meta, Google и xAI уже достигали передового уровня, тогда как OpenAI и Anthropic последовательнее его удерживали. Прежние проблемы Llama он связывает с политикой принятия решений, а риск для xAI — с текучестью кадров и недостатком организации. Это оценки Lambert, а не установленный разбор причин этих неудач.

У этого рассуждения есть экономическое продолжение. По оценке автора, разработка передовой модели теперь требует миллиардов долларов, поэтому прибыльный основной бизнес Meta, Google и Microsoft может дольше поддерживать конкуренцию с лабораториями, живущими за счёт самого ИИ. При этом меньшие разработчики могут строить востребованный бизнес без первого места в общих тестах. В статье нет расчёта стоимости обучения или доказательства, что деньги обеспечат лидерство: Lambert отдельно подчёркивает, что даже хорошие тестовые баллы пока не позволяют уверенно предсказать успех модели в реальной работе.

DeepSeek вынесла веб-поиск и чтение страниц в два самостоятельных API. Search возвращает структурированные результаты поиска, Fetch — заголовок и текст выбранной страницы в Markdown. Их можно подключить к агенту или к поиску документов для ответа модели, не используя отдельного поискового поставщика.

Search принимает запрос до 128 символов и возвращает от одного до 50 результатов. Можно ограничить домены, язык и даты публикации, запросить полный текст страницы. В ответе есть короткая выдержка для показа человеку и более длинная выжимка для модели. Fetch отдельно загружает один URL. Если сайт запрещает доступ или текст не извлекается, он возвращает ошибку.

Каждый API стоит 5 юаней за тысячу успешных запросов. Число результатов поиска на цену не влияет. Оплачивается только HTTP 200 с непустым списком результатов или извлечённым текстом. Ошибки, пустые ответы и таймауты бесплатны. У каждого API отдельный предел — пять запросов в секунду на аккаунт, а не на ключ. Для Fetch дополнительно действуют ограничения по домену. Это позволяет отдельно считать цену поиска и генерации, но не отменяет проверку качества найденного текста.

В первые две недели после запуска Search поиск через встроенные функции Claude Code и Codex заявлен бесплатным. Точную дату включения тарифа DeepSeek обещала объявить отдельно. Это временное исключение для этих интеграций, а не бесплатный доступ ко всем прямым вызовам API.

## Что из этого применить в платформе

**Проверить ограниченный ускоренный путь для изменений кода.** Редакционный вывод из Imprint — выбрать один класс нечувствительных изменений, описать допуск программными проверками и сравнить время до принятия с обычным путём. Отдельно учитывать ошибки и изменения, которым всё равно понадобился человек. Опыт автора, область кода и результат проверок должны проверяться повторно перед одобрением. Обязательное человеческое ревью там, где его требуют действующие правила, сохраняется.

**Проверить, что память помогает продолжать задачу.** Для Hy Memory взять несколько уже известных длинных задач, прерванных в разных местах. Сравнить обычное продолжение и продолжение с сохранёнными целями, решениями и условиями применимости опыта. Проверять нужно не только число восстановленных фактов, но и ошибочное применение устаревшего решения. Импорт истории инструментов требует отдельного разрешения пользователя. Стоимость подключения и результат внутренних внедрений Tencent публикация не раскрывает.

**Отдельно сравнить поиск и чтение страниц.** Для DeepSeek Search/Fetch повторить небольшой набор реальных запросов и URL. Проверить полноту результатов, даты, пригодность текста и фактически оплаченные успешные вызовы. Пять запросов в секунду на аккаунт и отдельные ограничения доменов учитывать до массовой загрузки. Временный бесплатный поиск через Claude Code/Codex не подменяет расчёт постоянного тарифа.

**Сравнить модели решений на составных вызовах.** Для нескольких узких решений по одному входу можно сравнить последовательные вызовы с одним многовопросным проходом, который появился у pplx-decider v1.2. Нужен один и тот же набор входов и критериев правильности. Ускорение без сохранения качества не будет выигрышем, а эксперимент Jev на OOLONG пока не раскрывает равноценность точности.

**Разделить причины нестабильности агента.** Перед заменой модели повторить несколько одних и тех же задач с фиксированной настройкой случайности и одинаковым представлением ответов инструментов. Сравнить, насколько меняются итог и последовательность действий. Наблюдение Hugging Face даёт две конкретные переменные для такого опыта, но не обещает полной повторяемости.

**В интерфейсе агента предусмотреть переход к человеку.** Сценарий Rokid показывает полезное разделение: простой запрос и текущий статус в одном интерфейсе, сложное подтверждение и исключение — в другом. Для одного нашего процесса можно явно перечислить точки, в которых агент передаёт управление человеку, и проверить, что при переходе сохраняются уже выбранные параметры. Это редакционное предложение, а не измеренный результат сервиса такси.
