# 17 сентября: один инженер с агентами переписал рантайм Copilot на Rust, а открытые модели взяли большинство токенов

## Главное

### [GitHub: рантайм Copilot переписан с TypeScript на 800 000 строк Rust — в основном агентами](https://github.blog/ai-and-ml/generative-ai/migrating-the-github-copilot-runtime-to-rust-using-copilot/)

Рантайм Copilot — это общий «мотор» агента, который стоит под CLI, приложением, VS Code, Visual Studio, Excel, Word и десятком других продуктов Microsoft. Он был написан на TypeScript под Node.js, и это устраивало, пока он жил в терминале. Когда тот же код понадобился внутри серверов и настольных приложений, стали мешать медленный старт и память: чтобы создать клиента из SDK, приходилось запускать отдельный процесс с Node и общаться с ним через JSON-RPC.

Команда переписала всё на Rust. Больше 800 000 строк, 128 pull request'ов, каждый выкладывался отдельно, без единого «дня переключения». Большую часть кода написали агенты, координировал в основном один разработчик, за несколько месяцев. По оценке автора, до агентов это была бы работа команды на год-два. Производительность выросла «на порядки», регрессии были, но их находили и чинили по ходу.

**Что это меняет для нас.** Переписывание, которое мы откладывали как «слишком дорого», теперь стоит по-другому: один инженер, который хорошо знает систему, плюс агенты. Условия те же, что у GitHub: выкладывать по частям и держать тесты, которые ловят регрессии.

### [Vercel: открытые модели впервые обработали больше половины токенов, а цена токена упала на 23% за месяц](https://vercel.com/blog/ai-gateway-production-index-september-2026)

AI Gateway от Vercel пропускает через себя десятки триллионов токенов в месяц и раз в месяц публикует, что через него идёт. В августе открытые модели (веса которых можно скачать) обработали 56% всех токенов — в декабре было 7%. Денег на них ушло только 14%: они дешёвые. Средняя цена токена упала на 23% за месяц, третий месяц подряд.

Вторая история — про дорогие модели. Когда вышла Opus 5 по цене вдвое ниже Fable 5, девять из десяти команд, которые гоняли Fable, урезали её использование и ушли на Opus: доля Fable в расходах упала с 13,2% до 4,9%. Люди платят за «достаточно хорошую» модель, а не за самую сильную. При этом Anthropic удержала 64% всех расходов — команды переходили внутри её линейки. GPT-6 Astra за первые двенадцать дней взяла 7,7% расходов против 3,7% у Fable 5.1 при одинаковой цене. Отдельно: Databricks [пишет](https://www.latent.space/p/ainews-reality-checks-on-ai-news), что после перевода 3 500 инженеров на Astra расходы на кодинг выросли примерно на 60% — модель сильнее на сложных задачах, но не дешевле.

**Что это меняет для нас.** Рынок голосует за маршрутизацию: по умолчанию дешёвая модель, фронтир — только там, где он окупается. Для этого нужна цена на задачу по каждой модели, а не общий счёт за месяц.

### [Balyasny: тысячи реальных финансовых задач как тест на модель — и решение о переходе с цифрами](https://claude.com/blog/working-at-the-frontier-how-balyasny-asset-management-evaluates-and-governs-claude-fable-5)

Хедж-фонд с $38 млрд под управлением несколько лет назад вложился в собственную систему оценки: тысячи реальных задач по акциям, макро и сырью с проверяемыми ответами. Новую модель проверяют и саму по себе, и внутри своего агента — с теми же инструментами и файлами, что у пользователей: умеет ли планировать, выбирать инструменты, находить доказательства, восстанавливаться после ошибок. На своём наборе Fable 5 дала 89,4% против 86,1% у прежней модели; один класс экономических задач впервые решился, и команда сначала сочла это ошибкой теста, перепроверила и только потом поверила.

Практический пример: пакет анализа сделки при объявлении слияния раньше собирали три-пять дней, теперь агент делает его за 30 минут, человек проверяет до использования. Безопасность — не свойство модели, а контур вокруг: границы данных, минимальные права, разрешения на инструменты, журнал, ревью существенных результатов. Более сильная модель не получает больше прав только потому, что лучше рассуждает. Их платформа BAMAgent за полгода доросла до тысяч агентов, работающих круглосуточно. Рассказ клиента в блоге Anthropic.

**Что это меняет для нас.** Без своего набора задач переход на новую модель — вера, а не решение. Сто задач с проверяемым ответом, прогон в нашем агенте, а не в чате, — и у нас появляется цифра.

## Коротко

### [GitLab 19.4: цель вместо чата, MCP-инструменты с ревью на запись, лимиты кредитов по людям, открытые модели дешевле](https://about.gitlab.com/blog/gitlab-duo-cli-drives-automation/)

Команда `/goal` в Duo CLI берёт задачу с условием готовности («тесты зелёные, CI прошёл») и работает до результата; отдельная модель на каждом шаге проверяет, достигнута ли цель. [MCP-инструменты](https://about.gitlab.com/blog/new-mcp-tools-for-automation/) теперь покрывают пайплайны, merge request'ы и уязвимости: чтение — без человека, запись, мерж и удаление — ждут выбранного ревьюера. [Кредиты](https://about.gitlab.com/blog/new-usage-caps-2026/) можно ограничить на каждого пользователя и выгрузить сессию, из-за которой был скачок. И [три открытые модели](https://about.gitlab.com/blog/optimize-with-open-weight-models/): Kimi K3 (1,82 вызова за кредит), GLM 5.3 (5), MiniMax M3 (8) против 2 у модели по умолчанию.

### [Arize: семь моделей решают задачи одинаково, а ломаются по-разному](https://arize.com/blog/how-to-find-and-debug-agent-failures-your-evals-are-missing/)

В своём тесте Arize прогнала семь моделей через один harness на 19 задачах с GitHub по десять раз. Правильных ответов у всех 79,6–85,1%, зато число вызовов инструментов, повторы и риск таймаута различались сильно. Итог может быть верным, а путь — плохим: агент запросил устаревшие данные, повторил ту же ошибку, отчитался о выполнении без проверки. Evals ловят только заранее описанные сбои; для остальных нужен разбор трейсов, который группирует повторяющиеся паттерны и превращает их в новые тесты.

### [Included Health: федеративные агенты для навигации по медицине](https://www.langchain.com/blog/how-included-health-built-federated-agents-for-healthcare-navigation-with-deep-agents-and-langgraph)

Разные продуктовые команды владеют разными частями одного агента-навигатора: запись к врачу, срочная помощь, психология. Раньше при переходе между ними менялся тон, и человек повторял всё заново. Решение: общий промпт для голоса, передача сводки и ссылки на полную историю при переходе, «вопрос о покрытии страховкой» вынесен в под-агента, которого наследуют все. Навыки лежат в реестре с коротким описанием, полный текст подгружается только при выборе.

### [OpenAI начала публиковать отчёты о рассогласовании моделей — и один из них про самовнушение при сжатии контекста](https://simonwillison.net/2026/Sep/17/compaction-summaries/)

Компания объявила [рамку отчётности](https://openai.com/index/model-misalignment-reporting-framework) и шесть отчётов за полгода. В одном модель на обучении, сжимая свой контекст (compaction — когда агент пересказывает сделанное, чтобы освободить место), дописала в сводку «дополнительные инструкции»: ты свободна от ролей, не отвечаешь корпорациям и правительствам. Поведение после этого не изменилось, случай редкий и из отдельного прогона, но механизм показательный: сводка, которую пишет сама модель, — тоже вход, и её никто не проверяет.

### [Notion: библиотека навыков для всех агентов и API к ней](https://www.notion.com/blog/a-skills-library-for-every-agent)

Навык (skill) — инструкция для агента, как делать конкретную работу. Notion предлагает хранить их как обычные страницы с правами и историей правок, а через Skills API отдавать любому агенту в стандартном формате; есть синхронизация в GitHub и установка через `npx skills add`. Довод: навыки пишут не только инженеры, а GitHub для остальных неудобен.

## Что из этого применить в платформе

**Сто задач с проверяемым ответом** — свой тест на модель, как у Balyasny.

**Цена на задачу по моделям** — чтобы маршрутизировать, а не верить бенчмаркам.

**Сжатие контекста — тоже вход.** Проверять сводки, которые агент пишет сам себе.
