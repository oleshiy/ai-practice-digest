# Инструменты и бенчмарки за 9–15 ноября 2026

### [XYBench](https://github.com/allenai/XYBench) — понимает ли модель, чего от неё действительно хотят.

13 ноября. Готовый бенч вопросов с ошибочной предпосылкой: проверяет и найденное решение, и то, на чём модель сосредоточила ответ. Я бы прогнал две привычные модели на 102 примерах `manually_curated` и посмотрел конкретные промахи. Python 3.10+, API через LiteLLM; отдельно оплачиваются ответы и судья, по умолчанию Claude. Данные англоязычные; исследование началось раньше ноябрьского анонса.

### [Pinky](https://github.com/DIYgod/pinky) — дать своему агенту телефон.

Новость 11 ноября, репозиторий появился 6-го. Готовое desktop-приложение соединяет Codex/Claude/Cursor с Android или iPhone через MCP. Проба: пройти форму в тестовом мобильном приложении, собрать скриншоты шагов и HTML-отчёт. Модель своя; нужны телефон либо Android-эмулятор и настройка подключения. Бесплатный открытый проект, но **pre-alpha**. Для iOS 17.4–26 нужен Mac/Xcode; у более новых версий другой способ подключения.

### [Quadknob](https://github.com/githubnext/quadknob-skill) — крутить результат агента руками.

11 ноября. Готовый skill добавляет в страницу четыре регулятора: отступы, шрифт, цвет, анимация. На одной карточке интерфейса можно выбрать понравившиеся значения и передать их агенту для переноса в код. Нужны существующий coding agent, браузер и Node/npx; новых модельных ключей нет. Это очень наглядная проба другого способа работать с агентом.

### [Kitesurf](https://github.com/cloudflare/kitesurf) — новый браузерный движок под того же агента.

Открыт 13 ноября. Подключить через CDP и дать пройти 3–5 страниц с формами и JavaScript, получить скриншоты. Интересно увидеть, где облегчённый движок уже заменяет привычный Chromium. Локально нужны Bazelisk, Node ≥22 и pnpm; сборка не мгновенная. Облако требует Workers Paid, локальная проба — нет. Совместимость пока экспериментальная.

### [ATLAS-Finance](https://github.com/Handshake-AI-Research/ATLAS-Finance) — посадить агента за банковскую задачу.

Разбор 9 ноября уже существовавшего бенча. Готовая среда с почтой, чатами, файлами и Excel: найти условия сделки и собрать расчёт с формулами. Взять одну задачу из smoke-конфигурации и прогнать своего Claude Code или Codex через Harbor. Нужны Docker, uv, доступ к Hugging Face, около 25 ГБ и API-ключи агента и проверяющего. На выходе — конкретный рабочий файл и видимые ошибки в применении условий.

### [Qwen Code 1.0 Preview](https://github.com/QwenLM/qwen-code/tree/v1.0.0-preview) — попробовать другую обвязку на своей модели.

Новость 11 ноября. Готовая CLI на ядре Qoder, с подключением стороннего совместимого API через Custom Provider; Qwen-веса не нужны. На маленьком временном репозитории дать ту же задачу своему обычному агенту и Qwen Code: посмотреть исследование кода, правку, тесты и diff. Нужны установка CLI и API-доступ; интерфейсы preview могут меняться.

### [OpenWorker Harness SDK](https://github.com/andrewyng/openworker/blob/main/harness/README.md) — собрать своего небольшого агента готовым конструктором.

13 ноября. Есть SDK, runnable-примеры и builder skill для Codex/Claude. Проба из README: агент раскладывает десять тестовых файлов, показывает действия и спрашивает подтверждения. Нужны Node/npm и модельный API; Rust runtime поставляется в npm-пакете. Получается работающий мини-агент с сохраняемой сессией; API SDK ещё развивается.

### [EGI-Bench](https://github.com/SalesforceAIResearch/egi-bench) — сравнить привычные модели на работе с документами и инструментами.

Статья 12 ноября об исследовании октября. Есть единый runner и отдельные наборы; начать с quick-поднабора HERB + PersonaBench, получить ответы, ссылки на доказательства и разбор ошибок. Python 3.12+, Node20, uv; нужен OpenAI API для штатных судей даже при тесте Claude. Модельные вызовы платные, лицензия — **только некоммерческое исследование**; полный quick занимает часы.

### [A2UI 1.0](https://github.com/a2ui-project/a2ui) — агент отвечает интерфейсом.

Релиз 11 ноября. В [Theater](https://a2ui-composer.ag-ui.com/theater) можно сразу посмотреть потоковые формы, карточки и выбор вариантов без установки. Проба — один экран уточнения заказа вместо переписки. Preview работает без Gemini; для живого ответа своей модели потребуется подключить SDK/renderer. Готовый Travel-demo с разговором использует Gemini, его как готовую замену вашей модели не предлагаю.

## Что из этого применить в платформе

Начать можно с трёх небольших проб: [XYBench](https://github.com/allenai/XYBench) — сравнить две модели на 102 готовых вопросах с ошибочной предпосылкой; [Pinky](https://github.com/DIYgod/pinky) — поручить агенту пройти форму на тестовом телефоне; [Quadknob](https://github.com/githubnext/quadknob-skill) — подобрать оформление одной карточки регуляторами и передать значения агенту. В первом случае нужны Python и оплачиваемый модельный API, во втором — подключённый телефон или Android-эмулятор и своя модель, в третьем — существующий coding agent, браузер и Node/npx. Pinky пока pre-alpha.

Для знакомства с ответами агента в виде интерфейса можно открыть [A2UI Theater](https://a2ui-composer.ag-ui.com/theater): просмотр готовых сценариев не требует установки и Gemini. Живой ответ своей модели — следующий отдельный шаг с подключением SDK и компонента, отображающего интерфейс.

Репозитории и инструкции проверены; сами инструменты не запускались. Вызовы моделей через API оплачиваются отдельно по тарифу провайдера. Для EGI-Bench действует ограничение: только некоммерческое исследование.
