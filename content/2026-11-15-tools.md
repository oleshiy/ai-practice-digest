# Три инструмента для работы с AI-агентами за 9–15 ноября 2026

### Pinky — агент управляет приложениями на вашем телефоне

Новость 11 ноября.

[Pinky](https://github.com/DIYgod/pinky) — открытое приложение, которое даёт AI-агенту читать экран Android или iPhone, нажимать кнопки и вводить текст. На компьютере оно подключает внешнего агента через MCP и управляет вашим телефоном по USB или Wi-Fi после разрешения на устройстве. Второй режим — задача прямо в приложении Pinky на телефоне: вы выбираете модель и указываете API-ключ, дальше оно работает без компьютера.

Можно поручить подготовить ответ в переписке, включив подтверждение отправки. Pinky остановит нажатие «Отправить»: разрешение проверяет сама программа. Контроль действует на действия через Pinky; агент с командной строкой должен быть изолирован от прямого доступа к телефону. Управление можно забрать. На компьютере сохраняются шаги, скриншоты, видео и HTML-отчёт. Интересно пройти целую мобильную задачу и увидеть, где агенту понадобилась помощь.

Проект в pre-alpha: поддерживает Android 10–17 и iOS 17.4+. Android-приложению нужны APK и разрешение специальных возможностей. На iOS 17.4–26 даже для управления с компьютера нужен помощник, установленный через Mac/Xcode. Для автономного iPhone-режима нужны Mac/Xcode и VPN: встроенный требует платного аккаунта разработчика Apple, с бесплатным используется LocalDevVPN.

### Qwen Code 1.0 Preview — готовый coding agent с выбором модели

Новость 11 ноября.

[Qwen Code 1.0 Preview](https://github.com/QwenLM/qwen-code/tree/v1.0.0-preview) — открытый агент для работы с кодом из терминала, объединяющий агентные возможности Qoder и Qwen Code. Вы запускаете его в каталоге проекта и описываете задачу. Программа связывает модель с файлами и инструментами: организует чтение кода, внесение изменений и запуск тестов, показывает запросы разрешений и сохраняет сессию для продолжения. Модель выбирает действия, а программа выполняет вызовы инструментов и возвращает ей результаты для следующего шага.

В README предложена конкретная задача: добавить проверку пустого имени проекта, соблюсти существующий стиль проверок и запустить соответствующие тесты. На выходе можно рассмотреть изменения через `/diff`, проверить результаты тестов и продолжить ту же сессию. Это готовый путь от поручения до проверяемой правки.

Через Custom Provider подключается совместимый API выбранной модели. Интересно дать Qwen Code и привычному агенту одинаковую задачу на одной модели: сравнить, какие файлы они изучили, как исправили код и что проверили. Так можно исследовать вклад программы, которая организует работу модели с инструментами. Устанавливается CLI для Windows, macOS или Linux; доступ и оплата зависят от модельного провайдера. Это preview: интерфейсы и настройки ещё могут меняться.

### A2UI 1.0 — общий язык интерактивных ответов агента

Релиз 11 ноября.

[A2UI](https://a2ui.org/concepts/overview/) — открытый протокол, по которому агент передаёт приложению описание интерактивного интерфейса. Разработчики задают каталог доступных карточек, полей и кнопок. Агент выбирает из него компоненты и связывает их с данными под текущий запрос. SDK проверяет описание по каталогу, а рендерер — библиотека внутри приложения — превращает его в настоящие элементы интерфейса.

В примере документации человек просит один билет из Берлина в Сан-Франциско и два обратно. Агент ищет рейсы и собирает две карточки со счётчиками пассажиров. Человек меняет числа прямо в карточках; кнопка подтверждения возвращает выбранные значения агенту. Получается экран, на котором можно уточнить и подтвердить результат за несколько действий, сохранив связь с исходным запросом.

Интересен общий договор между агентом и клиентами: одно описание может отобразиться в веб-приложении и на телефоне, если их рендереры поддерживают согласованный каталог. Разработчики один раз подключают компоненты и правила их использования, а агент собирает сочетания под разные запросы. Готовые SDK и рендереры позволяют попробовать этот цикл на одном сценарии: запрос, интерактивный ответ, исправление пользователем, продолжение работы агента. A2UI нужно встроить в приложение; доступ к данным, выполнение операций и проверка прав остаются у вашей системы. [Код и библиотеки](https://github.com/a2ui-project/a2ui).

## Что из этого применить в платформе

В [Pinky](https://github.com/DIYgod/pinky) можно начать с одной мобильной задачи: найти переписку и подготовить ответ, включив подтверждение отправки. Нужен телефон с настроенным подключением; проект пока pre-alpha. Если агент имеет доступ к командной строке, ему нужно запретить прямой доступ к телефону в обход Pinky.

Для [Qwen Code](https://github.com/QwenLM/qwen-code/tree/v1.0.0-preview) взять пример из README: добавить проверку пустого имени проекта, соблюсти существующий стиль и запустить тесты. На той же модели можно сравнить действия и итоговый diff с привычным агентом. Потребуются установка CLI и совместимый API выбранного провайдера.

В своём приложении можно попробовать [A2UI](https://a2ui.org/concepts/overview/) на одном цикле: агент предлагает карточки рейсов, пользователь меняет число пассажиров и подтверждает выбор, агент продолжает работу с выбранными значениями. Для этого нужны каталог компонентов, SDK и рендерер; данные, операции и права предоставляет ваша система.
