# Инструменты и бенчмарки за 9–15 ноября 2026

### XYBench — замечает ли модель ошибку в самом запросе.

Новость 13 ноября.

Пользователь просит разобрать XML регулярным выражением, хотя ему нужно извлечь данные и подошёл бы XML-парсер. Этот пример из README объясняет задачу [XYBench](https://github.com/allenai/XYBench): проверить, умеет ли модель обнаружить неудачно выбранный способ решения и предложить подходящий. Для каждого запроса записаны буквальная просьба, настоящая цель и критерии ответа. Готовые скрипты получают ответы моделей, затем модель-судья проверяет исправление заблуждения, предложенное решение и расставленные акценты. Можно начать со 102 вручную отобранных вопросов и посмотреть, где привычная модель послушно помогает делать ненужное. На выходе — ответы, оценки и сводка по моделям. Набор англоязычный; вызовы модели и судьи требуют API-доступа и расходуют его бюджет.

### Pinky — дать своему агенту руки на телефоне.

Новость 11 ноября; репозиторий появился 6 ноября.

[Pinky](https://github.com/DIYgod/pinky) подключает iPhone или Android к Codex, Claude Code и другим агентам через MCP — общий протокол доступа к инструментам. Агент читает экран, нажимает кнопки и вводит текст; пользователь видит происходящее на компьютере и может перехватить управление. Подтверждения контролирует сама программа: шаг, требующий одобрения пользователя, агент не может согласовать сам. Например, можно поручить подготовить сообщение и настроить остановку перед отправкой. В конце остаются шаги, скриншоты, запись экрана и HTML-отчёт. Нужен подключённый телефон либо эмулятор; для части версий iOS потребуется Mac с Xcode. Проект в pre-alpha, часть возможностей ещё ждёт проверки на реальных устройствах.

### Kitesurf — открывать веб-страницы без запуска Chromium.

Открыт 13 ноября.

[Kitesurf](https://github.com/cloudflare/kitesurf) — экспериментальный браузерный движок Cloudflare: разбирает HTML, применяет CSS, исполняет JavaScript и рисует страницу. Он принимает команды через CDP, протокол управления Chrome, поэтому к нему можно подключить знакомый Puppeteer и получать скриншоты. Интересен сам другой способ предоставить агенту браузер: страницы работают в изолированных Workers без контейнера с Chrome. Локально можно открыть собственную страницу с формой, заполнить её через Puppeteer и сравнить результат со скриншотом из Chromium. Это покажет конкретные расхождения в отрисовке и выполнении сценария. Потребуется сборка из исходников; совместимость с вебом и CDP неполная. Локальная проба доступна без платного облака, запуск в Cloudflare требует Workers Paid.

### Qwen Code 1.0 Preview — готовый coding agent с ядром Qoder и выбором модели.

Новость 11 ноября.

[Qwen Code 1.0 Preview](https://github.com/QwenLM/qwen-code/tree/v1.0.0-preview) объединяет агентные возможности Qoder и Qwen Code в открытом приложении для терминала. Оно связывает модель с файлами проекта и инструментами: читает код, вносит изменения, запускает тесты, запрашивает разрешения и сохраняет сессию для продолжения. Через Custom Provider можно подключить совместимый API своей модели; скачивать веса Qwen не требуется. В README предложено добавить проверку пустого имени проекта, соблюсти существующий стиль и запустить относящиеся к изменению тесты. Интересно дать ту же задачу обычному агенту на той же модели и сравнить действия, итоговый diff и проверки. Так можно исследовать вклад программы, организующей работу модели. Интерфейсы ещё меняются, оплата зависит от выбранного API.

### EGI-Bench — сравнить модели на поиске, действиях и многошаговой работе.

Статья 12 ноября об октябрьском исследовании.

[EGI-Bench](https://github.com/SalesforceAIResearch/egi-bench) объединяет восемь бенчмарков общим запуском и оценками по шести направлениям. Стенд подставляет выбранные модели в предусмотренные тестами процессы. Например, HERB просит найти автора документа и людей, обсуждавших его: сведения приходится связывать между документами, переписками и встречами. Вопросы без ответа проверяют, откажется ли модель выдумывать. Для действий есть MCP-Universe: в одном задании нужно получить биржевые данные, вычислить доходность вложения и пройти проверку результата. На выходе — JSON и сводка с исходными показателями и оценками направлений: видно, где модель ошибается. HERB и PersonaBench покрывают поиск по данным; для инструментов нужен другой набор. Подключение собственного готового агента потребует интеграции. Штатное оценивание использует OpenAI API; вызовы платные, вся quick-подборка занимает часы. Лицензия ограничивает использование некоммерческими исследованиями.

### A2UI 1.0 — собирать форму под запрос из компонентов приложения.

Релиз 11 ноября.

[A2UI](https://a2ui.org/concepts/overview/) позволяет агенту выбирать кнопки, поля и карточки из каталога, заданного разработчиками. Модель описывает нужный экран, библиотека проверяет описание и передаёт приложению структурированные сообщения. Приложение отображает их своими компонентами и может обновлять экран по мере ответа. В примере документации пользователь просит один билет из Берлина в Сан-Франциско и два обратно. После поиска рейсов агент собирает две карточки со счётчиками пассажиров. Человек меняет количество прямо в карточках, а подтверждённые значения возвращаются агенту. Такой сценарий можно повторить на своих данных: дать агенту карточку рейса, счётчик и кнопку, затем проверить разные сочетания пассажиров. Отдельную форму для каждого сочетания заранее рисовать не требуется. A2UI нужно встроить в приложение; модель, поиск, выполнение операций и проверку прав предоставляет ваша система.

## Что из этого применить в платформе

В [XYBench](https://github.com/allenai/XYBench) можно начать со 102 готовых вопросов: увидеть, где модель следует ошибочной предпосылке вместо решения задачи. Потребуются API модели и судьи. Для сравнения программ, управляющих одной и той же моделью, можно дать [Qwen Code](https://github.com/QwenLM/qwen-code/tree/v1.0.0-preview) и обычному агенту одинаковую небольшую правку, затем сопоставить действия, diff и выполненные тесты. Совместимый API подключается через Custom Provider; оплата зависит от провайдера.

Если агенту нужен мобильный интерфейс, [Pinky](https://github.com/DIYgod/pinky) позволяет попробовать подготовку сообщения с остановкой перед отправкой на подключённом телефоне или эмуляторе. Проект пока pre-alpha. Для интерфейса собственного приложения можно попробовать [A2UI](https://a2ui.org/concepts/overview/): дать агенту карточку рейса, счётчик пассажиров и кнопку, затем менять состав заказа прямо в карточках. Модель, поиск, операции и проверку прав должна предоставить сама система.
